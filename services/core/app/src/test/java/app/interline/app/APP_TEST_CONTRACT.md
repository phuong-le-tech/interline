# App acceptance test contract

These tests intentionally remain red against the M0 throwing production skeleton. No test installs controllers, a fake agent, a fake database, or an all-results facade.

- AC5, AC6 and AC9 use SpringBootTest RANDOM_PORT with InterlineApplication. Each scenario gets its own context, real MockAgent process and temporary data directory. Dynamic properties use `interline.data-dir`, `interline.log-dir`, `interline.agent`, indexed `interline.agent-args` and `interline.token`. These are proposed in-process test bindings; production must still receive the token on stdin, never argv or environment.
- AC11 starts `services/core/app/target/interline-core.jar` with Java 21, `--data-dir`, `--log-dir`, `--agent`, repeatable `--agent-arg`, and `--parent=stdio`. Run Maven package first so both executable jars exist. The MockAgent launcher is resolved to an absolute repository path.
- POST `/api/v1/recording/start` returns HTTP 200 and `{ "meetingId": "..." }`. Stop also returns HTTP 200. GET `/api/v1/meetings` and GET `/api/v1/meetings/{id}/transcript` return arrays. Transcript entries expose `stream`, `seg`, `speaker`, `startMs`, `endMs`, and `text`. Speaker labels are exactly `Me` and `Them`.
- SSE uses `event: recording.state` with `{meetingId,state}` and `event: stt.final` with `{meetingId,seg,...}`. Permission denial emits `recording.error` with `{meetingId,code:"permission_missing"}` and `capture.unavailable` with `{code:"permission_missing",...}`. Unknown event fields are ignored. These UI payload shapes are explicit test assumptions because the architecture names events but does not specify their JSON bodies.
- The fixture script is `fixtures/audio/standup-fr-2min.transcript.json`: sample_rate 16000, samples 1920000, and segments containing stream, seg, start_sample, end_sample and text. It has eight scripted French segments per stream. It is synthetic test content, not a recording or evidence of speech recognition quality.
- WAV generation is test-only: stereo PCM s16le, 16000 Hz, 120 seconds; left is mic, right is system. Inside each scripted region, sample i is `((i * step) % 20001) - 10000`, with step 37 for mic and 53 for system; outside these regions it is exactly zero. The expected mono bytes are computed separately, not read back from the WAV or from production output. This deterministic convention is not a production DSP restriction. The WAV is generated in the isolated data directory rather than checking a large binary into source control.
- Normal capture must store 1200 frames and 3840000 bytes per stream, as twelve numbered ten-second PCM files. Sequence high watermark is 1199; final STT watermark is 1920000 for both streams. Fixture segment end points deliberately reach the full duration on both tracks.
- Crash injection is `--crash-at=45s` at speed 20. A resumed MockAgent must not repeatedly inject the initial crash. The same meeting must have exactly two capture runs, first ending `agent_crash`, second `stopped`, exactly one gap marker, recording-degraded-recording SSE order, and every expected final exactly once. This test assumes replay preserves scripted sample positions. A real live-time restart gap is represented by a marker, not by silently shifting the fixture script.
- AC7 uses the proposed production `DurableCaptureIngest` ingress adapter. Its constructor, meeting creation, durable audio ingestion, atomic final-segment ingestion and close are throwing signatures only. The future recording pipeline must use this same adapter, not a separate test-only implementation. It must migrate/open `db.sqlite`, persist actual chunk files and capture-run watermarks, deduplicate audio on meeting/stream/sequence, and deduplicate finals on meeting/stream/seg. A duplicate frame returns the current contiguous durable acknowledgement. Reopening the adapter does not create a new capture run for an already persisted meeting. STT watermarks never regress on stale duplicate finals.
- AC11 covers explicit shutdown and stdin EOF, both idle and recording. Token input precedes exactly one READY JSON line; READY contains the real process pid, chosen port and nonempty version. No other stdout lines are allowed. Core and observed descendants must exit within six seconds with exit code zero. Failure cleanup forcibly terminates only the spawned core and its captured descendants.

- AC8 uses `PipelineAgentProbe` as a real test-only silent executable, not an out-of-scope MockAgent fault. Proposed `interline.agent-heartbeat-interval=50ms` scales its three-miss watchdog deadline; production default is 2s. Restart delays and the six-crashes-in-60s limit remain real. SSE must emit `capture.unavailable` and no seventh launch occurs.
- AC5 and AC6 run through a transparent test-only stdio tee to observe real ACKs, resume values and recovered flags. The ACK check proves bytes are readable before the ACK reaches the agent, not that the storage device honored fsync. Source/review verification of fsync-before-ACK remains required.
- AC5 also exercises the production `FixtureWav.generateIfMissing(Path, Path)` signature: missing-file generation, 120-second stereo s16le format, deterministic output, tone regions and exact silence outside the script.

No controller endpoints or lifecycle implementation are added by these tests. Missing behavior should fail assertions, such as HTTP 404 versus expected 200 or a missing READY line, rather than being replaced with mocked success.
