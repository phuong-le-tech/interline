# ADR-008 - Audio retention, consent and zero implicit network

Status: Accepted for M4, 2026-11-27.
Related: SPEC US-6.3, US-6.5, US-6.6; ADR-003, ADR-006, ADR-007, ADR-011.

## Decision

The core owns retention and deletion. Audio retention is `after_transcription`, `7d` (default), `30d` or `forever`. The preference is read when a meeting ends. Existing audio from before the upgrade keeps its null deadline and is never automatically scheduled. Changing the preference can only extend an existing non-null deadline for unpurged audio, or clear it with Keep forever. A shorter policy never brings an existing deadline forward; a null deadline is never rescheduled by a settings change. Deadlines use the end timestamp in milliseconds, never the creation date. A clock-driven daemon ticks every 60 seconds, including once at startup. It removes the canonical PCM and rescue-spool/recovery directories before clearing the audio reference. Notes and transcripts are untouched. Pending recovery work protects its input files. After-transcription deletion requires a successful agent drain or completed recovery; timeout-only completion keeps the audio (a -1 pending deadline) until transcription is confirmed.

Deleting a meeting first moves it to a 30-day trash. Restore clears the deletion timestamp. Permanent deletion requires a trashed meeting, commits a deletion-intent tombstone, removes only that meeting's canonical audio, spool and recovery directories, then deletes the meeting in one SQLite transaction. Existing foreign keys cascade capture runs, speakers, transcript segments, markers, recovery jobs, note blocks, snapshots, sources, AI runs, actions, briefs and participant links. FTS delete triggers remove search entries. People and calendar events are shared source records and remain. Missing rows and files make retries harmless. A failed file operation leaves the tombstone visible in trash and disables restore; maintenance retries it. There is no atomic transaction across SQLite and the filesystem, so an interrupted deletion can lose some files but cannot reappear as a complete live meeting.

Paths stored in the database never authorize deletion. Deletion derives `audio/<meeting-id>` `spool/<meeting-id>` and `recovery/<meeting-id>` from the injected data directory, rejects non-component meeting IDs and symlinked roots or meeting directories, and walks without following links. Recording cannot be trashed while writing. Local recovery may finish while a meeting is in trash so restore preserves its results. A failed recovery never prevents deletion. Once permanent deletion starts, late transcript deliveries are ignored. Permanent deletion holds the database monitor only to commit its tombstone and delete its rows; directory walking and removal run outside it so other meetings can keep ingesting. A lifecycle mutex serializes concurrent deletion retries, and the automatic purge rechecks trash eligibility when claiming the tombstone. User note text is never rewritten.

Consent remains an informational reminder before recording, with an explicit continue action and a local opt-out preference. It is not a substitute for the participants' agreement. Retention and delete controls describe what is removed; permanent deletion says it cannot be undone.

The shell runs `/usr/bin/fdesetup status` with fixed arguments, without a shell, on a worker thread. Its small `filevault.rs` parser maps successful, unambiguous output to `on` or `off`; failures, a two-second timeout and other output map to `unknown`. The UI warns in ochre for off or unknown and never blocks. This uses the existing Tauri command boundary instead of adding an agent protocol message or a JVM platform dependency, preserving ADR-003. v1 adds no application encryption. FileVault reports the macOS startup data volume; custom data directories on other volumes need a volume-specific check before such storage is supported.

The privacy catalog is computed from provider rows, the ICS secret-store configuration and the model catalog. It returns host names only, never private subscription addresses, user information, URL paths, query strings, secret account names or keys. Configured means available for an explicit request, not currently sending. When the agent secret store is unavailable, the endpoint returns 503 rather than guessing that a private subscription is off. LLM enhancement, brief and follow-up generation send selected context only after user action. Provider connection testing sends an authenticated model-list request. ICS fetches only on Sync; the five-minute calendar refresh reads local EventKit, not ICS. Model downloads start only on Download. There is no updater yet. EventKit, capture, transcription and secret storage use local agent IPC. There is no telemetry.

A source inventory test declares every outbound HTTP client, including `ConnectionTester`, and fails when a new client is introduced without updating the catalog. Opening this view never initiates outbound HTTP. All routes retain the local bearer, Host and Origin checks.

## Migration and rollback

V7 adds only deletion intent, due indexes and the default preference, without seeding any deadline or changing existing text. Audio that predates the upgrade is kept indefinitely unless the user deletes its meeting; automatic retention begins only when a meeting ends after the upgrade. Flyway runs it once; tests pin their target so later migrations cannot change their proof. Old clients continue to use the existing routes and ignore the new fields. Older cores do not maintain these deadlines or purge; do not run multiple core versions against one data directory. Rollback is a binary rollback with the additive schema retained, not a destructive down migration. Keep a backup before upgrading if data must be recoverable beyond its configured retention period: purged files and permanently deleted meetings cannot be reconstructed by rolling back code.
